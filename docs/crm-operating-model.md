# SZ Prime CRM Operating Model

## Purpose
The CRM is the shared operational memory of SZ Prime Solutions. Each customer should have one central identity, even when they use multiple business units.

## Core flow
1. Lead enters from WhatsApp, website, referral, phone or staff capture.
2. Customer is matched or created.
3. A service request is created.
4. The request is assigned to an SZ business unit.
5. The request is qualified.
6. A quote is issued where required.
7. Payment state is tracked.
8. A partner or internal operator is assigned.
9. Delivery is completed.
10. Feedback and follow-up are recorded.
11. Cross-sell and repeat opportunities remain visible.

## Shared customer fields
- Full name
- Phone
- Email
- Preferred language
- Location
- Acquisition source
- Consent/communication preference
- Service history
- Notes

## Service-request ownership
Every request must have:
- one primary business unit
- one current status
- one owner when staff accounts are introduced
- one source
- timestamps for auditability

## Initial statuses
- new
- qualified
- quoted
- awaiting_payment
- scheduled
- in_progress
- completed
- cancelled

## Human approval points
Human approval is required before:
- committing SZ Prime to non-standard pricing
- finalising high-value quotations
- making supplier commitments
- submitting tenders
- handling sensitive disputes or refunds
- overriding compliance checks

## Dashboard priorities
The first dashboard should answer:
- How many leads are open?
- Which unit owns each lead?
- Which customers are waiting for a quote?
- Which payments are outstanding?
- Which jobs are active?
- Which partner is assigned?
- Which customers have repeat/cross-sell potential?
- What revenue is attributable to each unit?
